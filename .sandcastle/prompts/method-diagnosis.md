# EXECUTION — DIAGNOSE → REPRODUCE → FIX

1. 建立反馈循环：优先用失败测试；其次使用带 fixture 的 CLI、HTTP 脚本、浏览器自动化或 trace 重放。必须能用一个实际运行过的命令捕获用户报告的具体症状。让信号尽可能快、确定且无需在线人工操作。偶发问题固定随机种子或提高复现率，记录失败频率。
2. 复现并缩小：确认捕获的是同一个问题；每次减少一项输入或条件并重新运行，保留导致症状的最小场景。无法复现时记录尝试和所缺证据，不能把猜测当根因。
3. 检验假设：列出 3–5 个可证伪的原因及预测，按证据排序；每次改变一个变量，用反馈循环验证。已由明确错误信息直接证明的简单问题可以说明理由后缩短此步。
4. 修复：先把最小复现固化为正确公共测试入口的回归测试，确认 RED，再实施最小修复使其 GREEN。原始复现场景也必须重跑。缺少合理测试入口时说明限制，避免用无法捕获真实症状的测试充数。
5. 清理：删除临时探针和调试输出，保留有价值的回归测试；交付说明包含证据支持的根因、修复和原始复现结果。

日志、命令和捕获内容必须先脱敏；凭据保留在环境中。普通测试失败也按这个反馈循环处理。没有复现证据时，不宣称已经定位根因。
