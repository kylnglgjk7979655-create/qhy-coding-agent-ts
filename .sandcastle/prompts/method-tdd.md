# EXECUTION — RED → GREEN → REPEAT

先探索需求涉及的公共接口和既有测试，写出本轮测试入口；优先使用规格已确定或仓库已存在的入口。必须改变公共接口且需求不足以决定时，报告具体决策阻塞。

每次完成一个可观察行为的纵向切片：
1. RED：写一个验证该行为的测试并实际运行，确认因目标行为缺失而失败。
2. GREEN：实现使该测试通过的最小正确修改。
3. REPEAT：继续下一个行为，直到当前任务的验收要求全部满足。

测试通过调用者使用的公共接口验证结果，覆盖真实用户行为；测试应在内部实现重构后仍然有效。预期值来自需求、独立计算示例或已知正确的固定结果。避免测试私有方法、内部调用顺序、按实现公式重新计算期望值，或一次写完全部测试再开始实现。

只在外部系统边界替换依赖：网络、第三方服务、时间、随机数等。已有本地测试数据库或文件系统 fixture 时优先使用它们。不要 mock 自己拥有的内部模块，也不要为了单独测试一个内部函数而随意增加对外接口。接口接收必要依赖，测试和生产经过相同的公共入口。
