# 消息级检查点按文件追踪记录，备份失败不阻止编辑

文件恢复采用追踪文件的方式，不保存整个工作区快照。各会话独立维护追踪范围，不因同工作区另一会话已经追踪某文件就自动纳入该文件。新消息开始处理时创建消息级检查点，检查已追踪文件的当前状态并保存变化；当受支持工具首次准备修改或创建某个文件时，保存其修改前状态并将其加入追踪。工具执行前继续进入备份流程，但交互界面只提供消息级检查点，不将每次工具执行前的版本单独列为恢复点。

追踪范围与 `.gitignore` 无关，凡受支持工具可以合法修改或创建的目标，均按同样规则追踪。检查点和文件备份持续保留，不自动过期或清理。

手动修改文件不会立即触发备份；只要文件已经进入追踪，其当前状态就在下一条消息开始时纳入检查点，不判断修改来源。例如检查点 1 对应首次工具编辑前的版本 A，工具将其改成 B，用户随后手动改成 C，则消息 2 的检查点记录 C。

检查点或文件备份失败时，记录错误后返回，继续消息处理与编辑，不以备份成功作为文件修改的前置条件。这一选择接受检查点数据可能缺失，以保持编辑操作可继续执行；恢复时若缺少必要备份，不允许仅恢复其中一部分文件。

代码恢复不删除未进入当前会话文件追踪范围的文件。已经纳入追踪、但在目标检查点时尚不存在的文件，在恢复时删除，并在预览中列明。

备份完整性与恢复执行错误采用不同规则：缺少必要备份时不开始恢复；开始恢复后，单个文件写入失败则记录该文件的错误，继续处理其余文件，不在首个错误处中止。例如恢复 `a.ts` 成功、恢复 `b.ts` 失败后，仍继续恢复 `c.ts`。因此执行结果可能部分成功，不能把“不允许缺少备份时部分恢复”解释为多文件恢复具有事务原子性。
