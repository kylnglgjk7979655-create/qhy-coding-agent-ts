# 文件工具限制在工作区内，并通过工具策略控制写入

工作区是内置文件工具的默认根目录；相对路径从工作区解析。`read_file` 和 `write_file` 可按权限规则或逐次审批访问工作区外的目标，符号链接权限按解析后的实际目标判断。`glob` 和 `grep` 默认搜索工作区；指定工作区外根目录时先审批，再按权限规则搜索，拒绝项从结果中排除。宿主 Bash 和 MCP 不受文件工具边界约束；工具权限不提供操作系统沙箱。

父需求 #6 的子任务 #9 替代初版“文件操作无需逐次确认”的约定：工作区内 `read_file`、`glob`、`grep` 和 `runtimeInfo` 默认允许，`write_file` 默认进入所选审批。新的 `permissions` 设置按能力和目标分别匹配文件路径、Bash 命令、MCP 工具及 Agent/RuntimeInfo；每类规则独立生效，冲突时 `deny` 优先，其次 `ask`，然后 `allow`。旧版 `approval.rules` 不再提供运行授权。批准发生在实际操作前，每次只适用于对应调用和参数；未知工具与无效参数先于审批被拒绝。

模型审批使用专用提示词、本次工具名称和完整参数，并可接收受控会话上下文：工作区和目标细节、权限规则、有效历史中的摘要、用户消息及先前工具调用参数和状态；不接收工具执行结果，也不具备工具执行能力。上下文可能不完整，不能核验完整用户意图。明确拒绝以权限拒绝工具结果回传，只影响当前调用；审批超时、不可用或无效响应停止本轮，保留此前副作用，不保存失败轮次。公共可等待审批控制与观察用执行事件分离，通知故障不改变审批决定。

工具策略和批准不能绕过权限规则的实际目标匹配；文件操作按规范化后的路径和解析后的符号链接目标匹配。除 `glob`、`grep` 外，工作区不是操作系统隔离边界；Bash、远程 MCP、其他进程及外部工具可访问或修改工作区外资源。普通文件操作失败按原有规则隔离，已发生副作用不自动回滚。

受控 `write_file` 在同一进程内检查每个 Agent 的读取基线，并串行完成版本检查与写入。主 Agent 的基线仅保留在当前 CLI 会话进程中；general-purpose 子 Agent 使用独立基线。Bash、远程 MCP、其他进程及外部工具可以绕过该协调，不保证避免写入冲突。

子任务 #10 增加可切换的人工审批：固定策略优先，终端按当前审批编号等待逐次批准或拒绝；非交互、输入关闭及等待超时直接拒绝本次调用。人工等待默认最多五分钟且单独计时，结束后继续使用整轮剩余执行时间，取消仍立即生效。完整参数仅在人工审批界面展示，执行事件保持只用于观察。
