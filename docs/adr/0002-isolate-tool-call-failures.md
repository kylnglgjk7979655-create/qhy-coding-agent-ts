# 工具调用失败按调用隔离，轮次故障立即停止

工具调用按主模型给出的顺序，通过共同 registry、工具策略、审批、结果和执行事件路径执行。文件、宿主 Bash 和远程 MCP 均使用这条路径；继续复用 SDK 的串行循环、schema 校验和调用 ID 关联，不另建调度系统。

父需求 #6 的子任务 #16 补全审批与对话摘要引入后的停止条件：

| 情况 | 行为 |
| --- | --- |
| 参数错误、未知工具 | 不审批、不启动实际操作，回传可区分的失败结果及拒绝事件，同批后续普通调用继续 |
| 固定策略拒绝、模型或人工明确拒绝 | 回传 `PERMISSION_DENIED`，不报告实际执行开始；只影响当前调用 |
| 普通文件失败、Bash 非零退出或单命令超时、MCP 远端声明的普通工具错误 | 回传 `TOOL_EXECUTION_ERROR` 及可用业务输出，同批后续普通调用继续 |
| 审批超时、不可用或响应无效 | 通知 `APPROVAL_ERROR`，停止本轮，不自动转人工或批准 |
| 摘要失败、无效、必要内容超预算或摘要后仍不满足目标 | 通知 `CONTEXT_ERROR`，停止本轮，不循环摘要、分段摘要或删除必要消息 |
| 父级取消、整轮超时、框架故障、调用与结果配对异常 | 停止本轮，不再启动后续工具或模型请求 |

成功工具结果保持 `is_error: false` 与 `output`；普通失败保持 `is_error: true` 与含 `code`、`message` 的 `error`。调用 ID 必须非空且在同批唯一，每次调用恰好对应一个结果。执行前可发现的无效 ID 阻止操作；不修复 ID、不为凑齐配对继续操作或补造结果。

实际启动的调用发出开始及唯一终结事件；观察通知同步或异步失败仅产生诊断，不改变审批决定或工具结果。普通事件和日志不打印完整参数、结果、文件内容、连接器凭据或原始异常；人工审批为说明待批准操作而展示完整参数，Bash 额外展示实际工作目录。审批控制是可等待的决定入口，不能由观察事件替代。

主模型、审查、摘要、MCP 连接与发现、工具执行均消耗整轮剩余时限，独立操作上限不能延长整轮时限。人工审批等待单独计时，等待结束后继续使用等待前的剩余预算，不重置此前消耗。审查和摘要不替代或重置主模型 `maxSteps`。

串行执行不提供事务或回滚保证，写入失败后的读取可能读到旧内容。轮次失败或取消保留此前文件、宿主和远端副作用；按 ADR 0004 增量保存完整 transcript，同时只将成功轮次交付的 `effectiveHistory` 作为后续续聊历史，失败时保留上次成功的有效历史。取消时不为尚未完成的工具调用补造结果。普通轮次错误后 CLI 可继续接收新消息，Ctrl+C 或 SIGTERM 则取消并退出。

MCP 独立断连、超时、取消及结果未知的专项边界按需求评论延期；本决策描述共用执行约束和基础接入，不据此声明延期场景已交付或验收。
