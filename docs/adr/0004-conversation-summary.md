# 对话摘要替换历史，仅随成功轮次保存

父需求 #6 的子任务 #14 在每轮首次主模型请求前检查上下文预算。预算包含内置系统提示、消息以及本轮实际可用的工具名称、描述和参数 schema；使用序列化载荷的字节数和消息开销估算，不声称与模型精确 token 数相同。容量、回答预留、触发阈值、压缩目标及完整保留轮数均经过严格配置校验。

默认达到可用输入预算的 80% 时，通过独立模型请求生成摘要，保留最近两轮完整对话及当前轮次，目标为压缩到预算的 50% 以下。按用户消息划分轮次，整轮保留工具调用与对应结果，不通过截断消息满足预算。摘要请求默认复用主模型配置，不暴露可执行工具；要求保留目标、已确认决策、约束、关键结果和未完成事项。

摘要以 assistant 历史资料替代较早消息，不能改变产品内置系统提示或工具策略；不将摘要作为 system 消息，不自动读取开发用 AGENTS.md 或发现运行时规则文件。公共运行入口的 effectiveHistory 是 CLI 保存与后续对话的唯一历史交付结果，responseMessages 仍表示当前轮次响应。

通过有效性及预算检查后，本轮使用替换后的内存历史；成功完成轮次后，沿用临时文件加原子替换，磁盘只保存摘要和保留消息。跨进程直接加载这份记录，旧格式历史保持可读并按需摘要。不建立被替换原文的归档、独立摘要副本或额外历史状态。接受信息损失：成功保存后无法从产品历史完整恢复被压缩原文。

摘要生成失败、响应无效、必要内容无法容纳或压缩后仍不达目标时，以明确轮次错误停止，不发送本轮后续主模型请求，不无限摘要或自动删消息。摘要成功后轮次失败或取消，同样不覆盖上次成功的磁盘和可续聊内存历史。已经发生的工具副作用不回滚。

摘要请求使用同一整轮取消信号并消耗剩余执行时限，取消和超时均停止后续处理。子任务 #15 负责同轮工具结果增长后的检查，以及独立审查和摘要请求自身的输入预算；本决策不将该后续范围计为已交付。
