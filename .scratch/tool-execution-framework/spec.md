# 工具执行框架

Status: ready-for-agent

## Problem Statement

CLI 用户需要 Agent 可靠地完成一组文件操作，并在某个工具失败时收到可继续处理的反馈。目前不同工具分别组织成功输出和错误信息，终端又只能在模型步骤结束后显示工具名称，用户难以及时判断工具是否正在执行、已经失败或根本未通过校验。

当模型在一次响应中提出多个工具调用时，用户还需要明确的执行顺序、调用与结果的正确对应，以及普通调用失败和整轮停止之间稳定的边界。维护者需要让多种工具共用执行与反馈路径，避免新增工具时重复处理参数校验、错误包装和进度通知。

## Solution

让现有三个工具通过统一路径完成参数校验、按序执行、结果反馈和进度展示。参数错误不执行工具，并向模型返回明确的失败结果；普通工具失败后继续处理同批后续调用，由模型结合各次结果决定下一步。

CLI 实时显示工具名称及开始、成功、失败或拒绝状态。调用与结果无法正确配对时阻止后续模型请求。保留现有 SDK、工作区边界、取消和超时行为，旧对话无需迁移即可继续使用，新调用使用统一结果格式。

## User Stories

1. 作为 CLI 用户，我希望现有运行信息、读文件和写文件工具使用一致的执行与反馈规则，以便理解不同工具的行为。
2. 作为 CLI 用户，我希望工具操作按模型提出的顺序执行，以便依赖先后顺序的文件操作获得可预期的结果。
3. 作为 CLI 用户，我希望同批写入成功后的读取能看到新内容，以便 Agent 根据实际修改继续工作。
4. 作为 CLI 用户，我希望同批写入失败后的读取仍然执行，以便 Agent 获得文件的实际状态。
5. 作为 CLI 用户，我希望模型同时收到失败调用和后续调用各自的结果，以便自行决定如何恢复任务。
6. 作为 CLI 用户，我希望文件不存在时返回可理解的工具错误，以便 Agent 解释问题或调整操作。
7. 作为 CLI 用户，我希望普通工具执行异常只影响单次调用，以便其他工具调用仍可完成。
8. 作为 CLI 用户，我希望读取参数中的未声明字段被拒绝，以免 Agent 误以为未支持的选项已经生效。
9. 作为 CLI 用户，我希望写入参数中的未声明字段被拒绝，以免错误请求产生文件修改。
10. 作为 CLI 用户，我希望缺少必填字段、字段类型错误或参数 JSON 无效时不执行读写工具，以便在请求正确前避免文件操作。
11. 作为 CLI 用户，我希望参数错误明确反馈给模型，以便模型纠正参数并重新调用。
12. 作为 CLI 用户，我希望工具不会暗中转换错误的参数类型，以便调用含义保持明确。
13. 作为 CLI 用户，我希望 runtimeInfo 保留接受并忽略额外对象字段的行为，以便此次重构不改变其既有兼容性。
14. 作为 CLI 用户，我希望调用不存在的工具时得到明确失败反馈，以便模型改用可用工具。
15. 作为 CLI 用户，我希望终端在工具实际开始执行时显示状态，以便知道 Agent 正在工作。
16. 作为 CLI 用户，我希望终端区分工具成功、执行失败和调用被拒绝，以便理解操作是否真正发生。
17. 作为 CLI 用户，我希望工具进度展示不输出完整参数和文件内容，以便终端保持清晰。
18. 作为 CLI 用户，我希望进度通知自身失败时不改变工具结果，以便已完成的操作不会被误报为失败。
19. 作为 CLI 用户，我希望文件访问继续限于工作区，以便工具执行范围保持明确。
20. 作为 CLI 用户，我希望工作区内文件操作继续直接执行，以便无需为每次已请求的读写重复确认。
21. 作为 CLI 用户，我希望文件操作失败后不自动回滚其他已完成操作，以便实际文件状态与各次工具结果一致。
22. 作为 CLI 用户，我希望 Ctrl+C 继续取消当前处理并退出 CLI，以便保留熟悉的中断方式。
23. 作为 CLI 用户，我希望整轮超时后仍能提交下一条消息，以便继续使用当前 CLI 会话。
24. 作为 CLI 用户，我希望达到模型步骤上限后不再请求模型，以便任务执行保持有界。
25. 作为 CLI 用户，我希望无法恢复的模型或框架故障明确结束当前轮次，以便不会在异常状态下继续执行。
26. 作为 CLI 用户，我希望只有成功完成的轮次被保存，以便续聊历史不混入未完成的交互。
27. 作为 CLI 用户，我希望旧对话记录无需转换即可继续使用，以便升级后仍能接着之前的任务工作。
28. 作为 CLI 用户，我希望采用新格式的工具结果能够保存并再次加载，以便后续续聊保持完整上下文。
29. 作为维护者，我希望所有工具的成功和失败结果具有统一外层结构，以便模型反馈和集成处理不再因工具而异。
30. 作为维护者，我希望参数错误、未知工具和执行失败使用不同错误码，以便准确诊断失败原因。
31. 作为维护者，我希望每个工具只维护一份参数 schema，并复用 SDK 校验，以便避免重复规则发生偏差。
32. 作为维护者，我希望复用 SDK 的模型循环、协议适配和串行执行能力，以便减少额外调度逻辑。
33. 作为维护者，我希望同批重复调用同名工具时仍按调用 ID 对应结果，以便不同调用的反馈不会混淆。
34. 作为维护者，我希望缺失、重复或无法配对的调用 ID 被直接拒绝，以便错误消息不会进入下一次模型请求。
35. 作为维护者，我希望只验证当前新增的工具往返而不修复旧历史，以便此次改造的范围明确。
36. 作为维护者，我希望执行事件包含足以定位调用的最小信息，以便展示和诊断可以共享同一通知来源。
37. 作为维护者，我希望新增工具可以复用公共执行与反馈能力，以便工具自身专注于参数定义和实际操作。
38. 作为维护者，我希望自动化检查验证真实工具消息的结构与 ID，以便测试不会因输出文本恰好包含目标字符串而误通过。
39. 作为维护者，我希望真实工具冒烟检查适配新的成功包装，以便继续验证工具结果确实进入模型回答。

## Implementation Decisions

### 职责与接入范围

- 保留现有 SDK 的模型循环、消息协议适配、schema 校验和工具调用 ID 关联；应用层负责统一结果、事件通知及新增工具往返的配对验证。
- 将通用执行与反馈逻辑从各工具的业务操作中抽出。运行信息、读取文件和写入文件三个现有工具全部接入同一公共路径；工具自身提供名称、描述、参数 schema 和执行逻辑。
- 复用 SDK 已有的串行工具执行能力，将工具调用并发度设为一，按照模型在同一响应中给出的顺序执行。仅关闭提供方的并行调用选项不能替代本地串行保证。
- 复用 SDK 校验结果，不重复实现参数字段校验；每个工具维护一份 schema。校验拒绝和未知工具也必须进入统一反馈路径，不能仅在实际执行函数内包装异常。

### 参数校验

- read_file 仍接收非空字符串 path；write_file 仍接收非空字符串 path 和字符串 content。保留现有字段含义与约束。
- 读写工具严格拒绝额外字段、缺少必填字段、错误字段类型和无效 JSON。拒绝时返回参数校验错误，不执行工具，不自动转换类型。
- runtimeInfo 保留现有空对象 schema 的宽松行为：接受对象并剥离额外字段，不改为严格拒绝额外字段。
- 参数校验失败与工具不存在属于单次调用失败，反馈给模型，并继续同批其他普通调用。

### 统一结果与错误分类

- 工具成功输出统一包含值为 false 的 is_error 和承载业务数据的 output。
- 工具失败输出统一包含值为 true 的 is_error 和承载 code、message 的 error。
- 成功 output 保留既有业务字段：runtimeInfo 返回 workspace 与 probe，read_file 返回 content，write_file 返回值为 true 的 success。
- 调用 ID 留在 SDK 外层调用及结果关联字段中，不重复嵌入业务输出。is_error 是应用层输出协议字段，不依赖提供方自动生成。
- INVALID_TOOL_ARGUMENTS 表示参数 JSON 无效或 schema 校验失败；UNKNOWN_TOOL 表示工具不存在；TOOL_EXECUTION_ERROR 表示文件访问失败或实际工具执行异常。
- 失败 message 应便于模型理解并保留现有文件访问错误信息，不返回原始异常或堆栈。
- 工具执行范围内的普通异常转为单次调用失败。取消、整轮超时、框架自身故障和配对异常通过轮次错误通路处理，不能包装成普通工具失败后继续执行。

### 顺序、配对与停止边界

- 一个工具批次是同一次模型响应提出的一组工具调用。普通工具调用失败不会跳过本批后续调用。
- 写入失败后继续读取：文件仍存在时可能读到旧内容，文件不存在时读取也失败。模型应同时收到写入失败及读取结果。
- 只验证当前新增工具往返：调用 ID 非空、同批唯一，每个调用恰好有一个对应结果，结果不得关联到错误或不存在的调用。不得按工具名称代替调用 ID 匹配。
- 执行前可发现的 ID 异常应在执行前拒绝。新增往返无法完整配对时直接报错，阻止下一次模型请求；不生成或改写 ID，不补造结果。
- 轮次已取消或失败时，不为凑齐配对继续执行工具或伪造结果。旧历史不因本次改造而增加全面配对扫描。
- 保留 maxSteps 和整轮 timeoutMs。达到步骤上限停止后续模型请求，保留现有步数耗尽报错；不新增单工具超时。
- 父级 abort、整轮超时、框架自身故障及无法恢复的模型、API 或流处理错误终止当前轮次，不再启动后续工具或模型请求。
- Ctrl+C 和 SIGTERM 保持取消并退出 CLI 的既有行为；整轮超时及普通轮次错误仍允许交互 CLI 接收下一条消息。
- 只有成功完成的对话轮次追加并保存历史。轮次失败不保存该轮交互，文件副作用不自动回滚。

### 执行事件与终端展示

- 执行事件状态分为开始、成功、失败、拒绝；最小载荷包含调用 ID、工具名、状态，可选携带错误码。
- 通过校验并进入实际操作时发出开始通知，完成后发出对应的成功或失败通知，不重复发送终结通知。
- 参数校验失败或未知工具直接发出拒绝通知，不伪造实际执行开始。
- CLI 展示工具名称与状态，不打印完整参数、完整结果、文件内容或原始异常；事件载荷也不携带这些内容。
- 事件用于观察，不承担主动停止职责，不持久化。通知处理失败只记录诊断，不修改工具结果，不中止后续调用；停止执行由取消信号及轮次错误控制。

### 文件边界与历史兼容

- 遵守工作区文件访问边界：相对路径从工作区解析，绝对路径仅在目标仍位于工作区内时接受；拒绝路径穿越及符号链接逃逸。工作区内操作无需逐次确认。
- 保留完整替换或创建文件、不自动创建缺失父目录的写入语义。
- 已保存的历史对话保持原样，不迁移旧工具输出，也不要求旧输出具有新的统一包装。旧、新格式可以在同一对话历史中共存。
- 新工具调用统一采用新输出协议，保存和重新加载后保持该协议。
- 同步调整工具冒烟检查，使其先识别新的成功包装，再检查 output 中的 content 与探针，以及模型最终回答中的探针。

## Testing Decisions

- 以现有编译后 CLI 为主要测试入口，通过本地 OpenAI 兼容 HTTP 模型服务夹具和临时工作区驱动完整工具往返。沿用现有交互 CLI 集成测试的结构，不为每个内部模块新增独立测试入口。
- 好的测试验证外部行为：实际发给模型的工具消息、工具调用 ID、终端状态、文件内容、后续请求次数、退出行为及保存的历史；不依赖内部函数调用顺序或私有模块组织。
- 测试覆盖公共工具执行与反馈能力、三个现有工具、CLI 进度展示、取消及限额行为、历史续聊和工具冒烟。复用已有读写、工作区边界、失败轮次不保存、步骤上限与中断测试作为先例。
- 扩展现有模型服务夹具，支持一次响应中多次工具调用、重复调用同名工具、不同 ID、错误参数和异常 ID。检查真正的工具角色消息，解析其业务输出并断言统一包装及关联 ID，不能仅搜索整段请求是否包含预期字符串。
- 验证三个工具的成功输出分别保留工作区与探针、文件内容、写入成功标记，且外层统一；验证未知工具、参数校验拒绝和执行异常均采用约定错误码及失败结构。
- 验证读写工具的额外字段、缺字段、类型错误和无效 JSON 被拒绝：收到参数错误和拒绝通知，文件没有被读取后反馈给模型或被写入修改；同时验证 runtimeInfo 仍剥离额外对象字段。
- 在同一模型响应内覆盖先写后读：写入成功后读取新内容；写入失败且原文件存在时读取旧内容；写入失败且文件不存在时读取也失败。各次调用结果均完整反馈，前一次普通失败不取消后续调用。
- 验证同批多次调用同名工具时按 ID 对应结果；ID 缺失、重复、结果缺失或错误关联时直接拒绝后续模型请求，且不生成修复消息。执行前能发现的异常不得产生文件操作。
- 验证实际执行显示开始与一次成功或失败，校验错误和未知工具显示拒绝；终端不输出完整参数或结果。
- 验证通知处理失败只产生诊断，工具结果仍正确且后续调用继续。优先通过现有运行边界支持的通知回调注入失败；若 CLI 主入口无法触发该故障，最多补充公共 Agent 运行入口的定向行为测试，不为内部执行器另开测试入口。
- 保留 Ctrl+C 退出、整轮超时后继续输入、步骤耗尽后停止模型请求、失败轮次不保存及工作区文件边界的回归覆盖。不以取消能够撤销已经发生的文件写入作为断言。
- 验证旧格式历史可继续对话，新格式工具结果能保存并再次续聊；旧历史内容不被迁移或强制包装。
- 保留本地工具冒烟集成检查和既有真实工具冒烟命令，验证新的成功包装能通过读取探针及最终回答检查。常规自动化验证优先使用本地夹具，不依赖真实模型服务。

## Out of Scope

- 新增工具，包括 Bash、Shell 或命令执行工具。
- 替换 SDK 的模型循环、协议适配或校验引擎，另建独立的通用调度系统。
- 多 Agent、子 Agent 或委派执行能力。
- Hook 主动停止机制、上下文恢复、新的 maxTurns 配置或自动恢复流程。
- 调用 ID 自动生成修复、结果补造、历史配对修复、严格与默认修复两套模式。
- 工具并行调度、依赖图、事务、文件回滚或单工具超时。
- 执行事件持久化、重放、进程重启恢复，以及将进度通知作为模型工具结果。
- 将 runtimeInfo 改为严格空对象校验。
- 将 Ctrl+C 改为仅取消本轮并返回输入。
- 批量迁移旧历史、访问工作区外文件或新增逐次文件操作确认。

## Further Notes

- 术语使用“对话”“对话轮次”“工具调用”“工具批次”“工具结果”和“执行事件”，保持与领域术语表一致。
- 遵守工作区文件访问及工具调用失败隔离两项现有架构决策。
- 本规格的执行事件展示在既有工具名称提示上增加状态，参数和完整结果仍只交给 Agent。
- Status 为 ready-for-agent，可据此开展实现。
