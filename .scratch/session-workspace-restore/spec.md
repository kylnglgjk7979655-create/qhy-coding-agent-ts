# Session 工作现场恢复

Status: ready-for-agent
Issue: https://github.com/kylnglgjk7979655-create/qhy-coding-agent-ts/issues/23

## Problem Statement

CLI 用户希望退出、主动中断或进程意外结束后，仍能找到之前的会话，恢复对话和运行配置，并在需要时把代码恢复到某条消息对应的文件现场。

当前持久化只保存成功轮次交付的消息数组。工作区、模型和其他运行配置每次启动重新读取；数据跟随启动目录，缺少会话选择与代码恢复入口。失败或中断轮次的操作记录会丢失，摘要成功保存后较早原文也会被替换。用户即使拿到原 conversation ID，也无法恢复完整工作上下文。

同一工作区的多个会话共用文件目录，因此恢复对话与恢复代码必须分别由用户控制。文件备份、完整会话记录和多文件恢复的错误行为也需要明确区分。

## Solution

引入可恢复的会话，以 session transcript 保存完整原文、运行配置、轮次状态、摘要及代码恢复记录。会话数据统一存放在用户级根目录，默认采用 `~/.qhy-coding-agents/`。继续会话时使用 transcript 中最后生效的配置，摘要用于构造模型输入，原文持续保留。

沿用逐行 CLI，提供 `/new`、`/resume [id]`、`/rewind`、`/exit`。会话选择默认展示当前工作区，并可查看全部会话。继续或切换会话使用当前文件；只有用户主动选择文件恢复指令、查看受影响文件与改动统计并确认后，才执行代码恢复。

以受支持文件修改工具驱动文件追踪，在新消息开始时建立消息级检查点，并在工具修改或创建文件前保存原状态。首版支持 `write_file`；每个会话独立维护追踪范围，文件备份与 Git 忽略规则无关。

## User Stories

1. 作为 CLI 用户，我希望新会话有独立标识和 transcript，以便后续准确找到并继续这次工作。
2. 作为 CLI 用户，我希望通过 `/new` 在当前工作区新建空会话，以便开始另一项任务而保留现有会话。
3. 作为 CLI 用户，我希望通过 `/resume` 查看当前工作区的会话列表，以便选择要继续的工作。
4. 作为 CLI 用户，我希望能够查看全部工作区的会话，以便找到其他项目的既有会话。
5. 作为 CLI 用户，我希望通过 `/resume <id>` 直接继续指定会话，以便使用已知标识快速恢复。
6. 作为 CLI 用户，我希望指定不存在的会话时明确报错，以便区分继续会话与新建会话。
7. 作为 CLI 用户，我希望从不同启动目录仍能找到同一会话，以便会话存储不依赖启动命令的位置。
8. 作为 CLI 用户，我希望一个工作区可以有多个独立会话，以便分别处理不同任务。
9. 作为 CLI 用户，我希望这些会话共用工作目录，以便在原项目目录中继续编辑文件。
10. 作为 CLI 用户，我希望继续或切换会话时保持当前文件内容，以便选择会话不会自动触发代码还原。
11. 作为 CLI 用户，我希望会话恢复到原工作区，以便旧历史与配置对应正确的项目。
12. 作为 CLI 用户，我希望原工作区移动或失效时恢复报错，以便不会把旧会话默默关联到另一个目录。
13. 作为 CLI 用户，我希望续聊使用 transcript 中最后生效的模型和运行配置，以便恢复之前的运行上下文。
14. 作为 CLI 用户，我希望凭据从当前环境读取，以便会话记录保存配置引用而不保存凭据值。
15. 作为 CLI 用户，我希望 transcript 保留完整消息与工具往返原文，以便历史可被查看并用于恢复。
16. 作为 CLI 用户，我希望失败和中断的轮次也留下记录，以便了解已经发生的操作与未完成事项。
17. 作为 CLI 用户，我希望长对话可以用摘要构造模型输入，同时保留原文，以便控制上下文占用并保留完整记录。
18. 作为 CLI 用户，我希望恢复时复用已有摘要及覆盖范围，以便不必每次重新压缩同一段历史。
19. 作为 CLI 用户，我希望处理中按 Ctrl+C 只结束当前轮次并返回输入，以便可以继续使用当前 CLI。
20. 作为 CLI 用户，我希望用户主动中断的未完成调用结果为 `Interrupt by user`，以便后续 Agent 能识别这是用户主动停止。
21. 作为 CLI 用户，我希望空闲时按 Ctrl+C 或输入 `/exit` 退出，以便明确结束 CLI 使用。
22. 作为 CLI 用户，我希望断电后没有任何结果的工具调用不进入恢复上下文，以便不把孤立调用发送给模型。
23. 作为 CLI 用户，我希望断电前已经保存的部分工具结果进入恢复上下文，以便 Agent 利用已经观察到的信息。
24. 作为 CLI 用户，我希望原始 transcript 不因上下文过滤而删除记录，以便历史留存与模型输入分别满足各自用途。
25. 作为 CLI 用户，我希望同一会话不能被两个进程同时使用，以便避免它们覆盖或交叉写入同一份记录。
26. 作为 CLI 用户，我希望异常退出后仍能再次使用原会话，以便进程占用不会永久阻塞恢复。
27. 作为 CLI 用户，我希望每条新消息开始处理时建立检查点，以便按消息选择代码恢复位置。
28. 作为 CLI 用户，我希望受支持工具首次准备修改或创建文件时备份原状态并纳入追踪，以便能够恢复工具编辑前的内容。
29. 作为 CLI 用户，我希望已追踪文件的手动变化在下一条消息开始时保存，以便后续检查点包含当时实际文件状态。
30. 作为 CLI 用户，我希望各会话独立维护文件追踪范围，以便另一个会话的追踪记录不会自动变成当前会话的记录。
31. 作为 CLI 用户，我希望被 Git 忽略的合法工具目标也能被追踪，以便备份行为与 `.gitignore` 无关。
32. 作为 CLI 用户，我希望同一消息中的多次文件编辑保留本条消息的初始恢复基线，以便恢复到消息开始前的已保存状态。
33. 作为 CLI 用户，我希望文件首次备份可作为此前检查点的恢复基线，以便回退较早消息时仍能撤销后续受支持工具编辑。
34. 作为 CLI 用户，我希望明确追踪前未保存的内容无法重建，以便理解早期检查点实际可恢复的范围。
35. 作为 CLI 用户，我希望通过 `/rewind` 选择消息级检查点，以便主动恢复代码。
36. 作为 CLI 用户，我希望恢复前看到受影响文件和改动统计，以便决定是否执行恢复。
37. 作为 CLI 用户，我希望可以取消恢复确认而保持文件现状，以便查看预览后再作决定。
38. 作为 CLI 用户，我希望恢复预览不判断修改来自谁，以便统一按文件差异选择恢复。
39. 作为 CLI 用户，我希望预览后、确认前文件又变化时刷新预览并重新确认，以便看到与当前文件对应的恢复改动。
40. 作为 CLI 用户，我希望未追踪文件保持现状，以便恢复只作用于当前会话的追踪范围。
41. 作为 CLI 用户，我希望恢复到追踪文件创建前时删除该文件，以便还原其原本不存在的状态。
42. 作为 CLI 用户，我希望代码恢复保留对话，以便继续参考之前的讨论和操作过程。
43. 作为 CLI 用户，我希望恢复目标及逐文件成功、失败结果写入 transcript 并提供给 Agent，以便它知道恢复后的实际状态。
44. 作为 CLI 用户，我希望检查点或文件备份失败只记录错误，以便不会阻止原本的编辑操作。
45. 作为 CLI 用户，我希望必要备份缺失时不开始恢复，以便不会只恢复其中有备份的一部分文件。
46. 作为 CLI 用户，我希望恢复中某个文件失败时记录错误并继续其他文件，以便一次局部写入失败不阻止剩余恢复操作。
47. 作为 CLI 用户，我希望 transcript 写入失败时停止本轮后续处理，以便续聊依据失效后不会继续产生新操作。
48. 作为 CLI 用户，我希望失败或中断后保留已经发生的文件修改，以便记录状态不会被误认为能回滚所有工具副作用。
49. 作为 CLI 用户，我希望 transcript、检查点和备份一直保留，以便不会因自动过期而失去恢复记录。
50. 作为 CLI 用户，我希望文件恢复继续遵守工作区和符号链接边界，以便检查点不会扩大文件访问范围。

## Implementation Decisions

1. **会话协调与单轮运行分开。** CLI 负责当前会话、命令分派、工作区、会话占用和记录生命周期；单轮运行保留现有模型与工具循环。一个会话对应自身 transcript，不建立 fork 或会话内多分支模型。
2. **完整记录与有效历史分开。** 扩展运行过程的记录能力，收集消息、工具调用与结果、可观察的部分输出、轮次终态及配置，不依赖成功轮次返回后才持久化。现有轮次结果中的有效历史继续表达模型使用的上下文，不再是完整会话原文的唯一交付来源。
3. **恢复配置以 transcript 为准。** 新会话使用启动配置，工作区取当前工作区；恢复使用目标会话最后生效的配置，当前启动配置不能默默覆盖它。保存凭据环境变量引用，实际凭据从当前环境解析。首版没有会话内配置编辑入口。
4. **用户级统一存储。** 会话、检查点及文件版本归属于会话标识，跨启动目录可查找；默认根目录见方案。会话绑定原工作区，禁止通过重新指定目录来迁移旧会话。
5. **逐行交互。** 采用已确认的四个斜杠命令及编号选择列表。会话列表默认当前工作区，可查看全部；选择其他工作区的会话时使用其原工作区。既有启动时指定会话的入口遵循同一恢复规则，指定不存在的会话均报错。
6. **继续会话与恢复代码分开。** 新建、继续或切换会话都不自动恢复文件。文件恢复由用户选择检查点并确认触发，保留对话，并将实际恢复结果纳入 transcript 与后续上下文。
7. **每会话独立追踪。** 首版只有 `write_file` 触发目标文件追踪。Bash、MCP 不作为追踪入口，不提供任意外部副作用的恢复保证。已追踪文件在后续检查点中的变化不按修改来源分类。
8. **消息级检查点。** 新消息开始处理时创建检查点，检测已追踪文件的变化并保存当前状态。工具修改或创建文件前执行备份流程，首次目标纳入追踪；原本不存在也是一种必须记录的状态。界面不单列工具级恢复点。
9. **稳定的消息基线。** 同一消息多次写入同一文件，不能用后续工具前版本覆盖本条消息的初始恢复基线。手动变化不立即触发备份，下条消息开始时再保存。
10. **首次备份补齐早期恢复基线。** 文件首次备份作为此前检查点的恢复基线；追踪前从未保存的版本不能重建。失败而缺失的备份不能被当作有效修改前版本，适用恢复前完整性检查。
11. **统一的合法目标范围。** 不按 Git 忽略规则排除受支持工具的合法目标；备份与恢复继续遵守既有工作区、路径及符号链接边界。备份接入实际执行前可等待的路径，不能仅依赖不会等待的执行观察通知；既有工具策略和审批继续有效。
12. **恢复预览与确认。** 先校验必要备份齐全，再展示受影响文件、删除项和改动统计。用户确认后执行，取消则不修改文件。预览不识别来源，不增加针对手动修改的单独覆盖提示；确认前检测到文件变化时重新预览、重新确认。
13. **恢复文件状态。** 仅处理当前会话追踪范围。目标状态为不存在时删除相应追踪文件；未追踪文件保持现状。新消息以恢复后的实际文件状态继续建立检查点。
14. **错误分为四类。** 检查点或文件备份失败只记错、继续处理与编辑；transcript 写入失败停止本轮后续模型与工具操作；恢复前缺少必要备份则不开始恢复；恢复执行中单文件失败则记错并继续其他文件。执行阶段不要求多文件事务回滚，已发生副作用保留。
15. **工具中断按原因投影。** 用户主动中断时，未完成调用的结果内容为精确字符串 `Interrupt by user`。断电后无任何已保存结果的调用从模型上下文中过滤，但原始记录保留；有部分结果则保留对应调用和真实已保存输出，明确没有观察到最终结果。
16. **保留协议约束。** 恢复后的模型输入须保持原始调用 ID 与结果配对；不发送孤立调用，不伪造未观察到的退出码或成功状态。完整原文保留不意味着原样发送每条记录，也不授权自动重放未完成调用。
17. **取消作用域。** 活动轮次 Ctrl+C 取消本轮及后续操作，记录用户中断、等待受管理操作结束后返回输入；下一轮仍能正常运行。空闲 Ctrl+C 退出。已有宿主进程终止与副作用不回滚规则继续有效。
18. **单会话占用。** 同一会话不允许两个进程同时使用；正常退出解除占用，异常退出后可再次恢复，不得遗留永久占用。拒绝第二个使用者不能影响第一个进程。
19. **复用摘要。** Transcript 保留完整原文，并记录通过有效性与预算校验的摘要及覆盖范围。恢复复用已保存摘要，再接上后续消息。摘要仍是历史资料，预算检查、完整工具配对及原有停止规则继续适用。
20. **持久化与留存。** 按处理进展持续保存，以已经成功保存的记录进行断电恢复；半写入记录不得污染此前完整数据，不可恢复的损坏明确报错。记录、检查点和备份一直保留，不自动过期或清理。
21. **内部编码不绑定实现布局。** 事件编码、根目录内部层次、版本去重、进程占用机制及内部模块接口由实现阶段细化，须保留稳定的会话、轮次、调用、检查点和文件版本关联，满足上述外部行为。

## Testing Decisions

1. **用户已确认主测试入口。** 统一使用编译后 CLI 子进程、本地 OpenAI 兼容模型夹具、临时用户目录与工作区；通过 stdin、信号和多个进程驱动真实应用，检查 stdout、stderr、退出行为、文件、持久化记录及后续模型请求。
2. **最高公共边界优先。** 好的测试描述用户可观察的行为与失败后的状态，不断言私有函数、调用次数、内部缓存或具体版本去重布局，不为测试增加产品专用入口。扩展现有 CLI 测试驱动以支持逐步输入、启动不带会话 ID、不同启动目录及临时用户目录。
3. **测试能力覆盖。** 从同一 CLI 入口验证会话协调与存储、配置恢复、模型上下文重建、摘要复用、文件追踪、恢复预览、逐文件恢复、取消及进程占用；不以拆出多个内部模块测试入口替代这些行为验收。
4. **参考既有实现。** 复用交互 CLI 的子进程与跨进程续聊模式、本地模型服务的请求观察与流式响应夹具、上下文摘要的预算及配对断言、Bash 的真实进程与部分输出观察，以及人工审批测试已有的终端驱动经验。
5. **新建、列表与继续。** 覆盖四个命令，当前工作区及全部会话选择、直接指定 ID、未知 ID 报错、跨启动目录查找、使用 transcript 配置、凭据从当前环境解析、原工作区失效报错和切换不改文件。
6. **首次与后续备份。** 通过真实 `write_file` 调用验证首次原内容备份、创建前不存在状态、同消息多次编辑的基线、已追踪文件下一消息时保存当前状态、会话间独立追踪、Git 忽略规则不影响追踪。
7. **两个已确认版本场景必须覆盖。** 一是检查点 1 备份 A、助手改 B、用户手动改 C、消息 2 保存 C，两个检查点分别恢复 A 与 C；二是消息 1 的 A 未追踪、手动改 B、消息 2 首次备份 B，恢复消息 1 使用 B。
8. **恢复预览与结果。** 验证消息级选择、文件列表与统计、用户取消不写入、确认后恢复、预览后发生外部修改时刷新并重新确认、未追踪文件不受影响、目标不存在时删除、对话保留、下一次模型请求能看到真实恢复结果。
9. **区分四类错误。** 使用临时文件系统的真实错误条件验证备份失败仍编辑、transcript 失败停止后续请求和工具、必要备份缺失时零恢复写入，以及恢复中第一个文件成功、第二个失败、第三个仍被处理。观察最终文件与记录，不通过私有函数 mock 判定。
10. **用户中断与断电分开。** Ctrl+C 后验证未完成调用的中断结果及同进程下一轮成功；强制结束进程后重启，分别验证无结果调用过滤、有部分结果调用保留、原 transcript 不删、上下文调用配对正确。以记录落盘和进程可观察事件同步，避免依赖固定睡眠猜测时序。
11. **摘要与原文。** 用本地夹具触发摘要，验证原文仍持久存在，恢复后的请求复用摘要及正确覆盖边界，后续消息不丢失、不重复，摘要不会放宽系统提示或工具策略。
12. **并发与异常退出。** 两个真实 CLI 进程竞争同一会话，第二个被拒绝且第一个仍正常；强制结束占用者后可再次恢复。临时用户目录隔离测试，不能写入真实用户会话根目录。
13. **更新已经改变的旧断言。** 原有“失败轮次不保存”“摘要后原文消失”“不存在的 ID 新建”“Ctrl+C 总是退出”和依赖启动目录存储的断言，按本规格调整；审批、路径边界、工具配对、预算与宿主副作用回归继续保留。
14. **验证方式。** 实现后先运行相关 CLI 集成用例，再运行仓库标准检查。终端列表、检查点预览及 Ctrl+C 连续交互需要人工检查；自动测试结果不能声称人工检查已完成。本次规格编写不运行未来实现测试。

## Out of Scope

- 会话 fork、会话内多分支或分支历史管理。
- 为不同会话创建隔离目录或 Git worktree。
- 工作区移动、改名后重新绑定原会话。
- 旧格式对话的自动迁移或手动导入。
- 全屏 TUI、会话内运行配置编辑，以及已确认四个命令之外的新管理入口。
- 独立工具级恢复点、成功轮次结束后新增恢复点或手动建立检查点的命令。
- 把整个工作区、Git 状态、shell 环境或后台服务作为系统快照恢复。
- 任意 Bash、MCP、工作区外文件或远端副作用的自动追踪、还原保证。
- 专门识别修改来自用户，并增加相应覆盖提示。
- 自动过期清理、恢复时自动回滚全部成功文件，以及多文件事务原子性保证。
- 为恢复历史新增真实模型服务依赖、凭据存储方式或产品内部测试开关。
