# Session 工作现场恢复：设计访谈

## 已确认

- 本次完善 session 的主线是“恢复完整工作现场”（用户选择首轮选项 C）。
- Q2 选择 A+B：恢复对话、工作区、模型及相关运行配置，并支持恢复代码与未提交修改等文件现场。具体保存触发点见 Q5/Q7，文件恢复交互见 Q6。
- Q3 选择 B：保留中断记录，让用户了解原始请求、已完成操作与中断位置，再决定如何继续。中断记录的具体保证及处理方式仍待确认。
- 领域语言中区分“会话（Session）”与“对话”：前者表示可恢复的工作上下文，后者表示消息历史；session transcript 是该会话的完整记录。
- Q4 已确认：一个工作区可以有多个会话，每个会话独立恢复；多个会话共用工作目录，不使用隔离目录。“独立恢复”不代表同时拥有彼此独立的磁盘文件状态。
- Q5 澄清“每轮”：指用户提交一条消息到 Agent 给出最终回复的一次对话轮次，包含中间的模型请求与工具往返；不是整个会话。
- Q5 已确认的文件现场保存触发点：新消息开始处理时；调用受支持的文件修改工具前。工具范围见 Q8，追踪规则见 Q7。此前建议的成功轮次结束后自动保存、允许手动存档，均未获确认。
- Q6 已确认：继续或切换会话时不会自动还原文件内容。交互界面在执行代码恢复前展示受影响的文件和改动统计，由用户选择是否恢复；不专门识别修改是否由用户手动完成，也不单独提示这类修改将被覆盖。已记录到 `docs/adr/0005-shared-workspace-explicit-code-restore.md`。
- Q8 已确认：首版仅支持内置 `write_file` 触发文件追踪；Bash 和 MCP 不作为追踪入口，不承诺恢复它们的任意副作用。根据 Q7，已追踪文件的后续变化会在新消息检查点纳入，不按来源区分。
- Q9 已确认：恢复代码时保留已有对话。恢复操作如何记录、如何向 Agent 呈现仍待细化。
- Q7 已确认：使用文件追踪；受支持工具准备修改或创建文件时，先备份其原状态并加入追踪。新消息开始时为已追踪文件检测变化、保存当前版本；用户手动修改不会立即备份。
- Q7 用户给出的场景：发送消息 1 创建检查点 1；首次编辑 `a.ts` 前备份 A 并纳入追踪；助手改成 B；用户手动改成 C，不立即备份；发送消息 2 创建检查点 2，检测到变化并备份 C。因此检查点 1 对应 A，检查点 2 对应 C。
- Q10 已确认：恢复入口仅展示消息级检查点。
- Q11 已确认：检查点或文件备份失败时，记录错误后返回，不影响编辑操作。不能实现成备份失败即阻止 `write_file`。
- Q7/Q10/Q11 已记录到 `docs/adr/0006-message-checkpoints-track-files.md`。
- Q12 已确认：文件不在追踪范围内就不删除；受支持工具创建且已纳入追踪的文件，恢复到创建前的检查点时删除。
- Q13 已确认：缺少必要备份时不允许只恢复有备份的文件，应在恢复前检查完整性。这不改变 Q11 的备份失败不阻止编辑，也不等于执行中途错误时必须回滚。
- Q14 已确认：各会话独立维护文件追踪范围。
- Q15 已确认：恢复执行期间逐文件处理，单文件失败时记录错误、继续后续文件。用户给出的例子：恢复 `a.ts` 成功，恢复 `b.ts` 写入失败，记录 `b.ts` 错误后继续处理 `c.ts`。不能实现为遇到首个错误即停止，也不能声称多文件恢复具备全有或全无的保证。
- Q16 已确认：本次不需要 fork，不建立会话内多分支模型。
- Q17 已确认：运行配置以 transcript 为准。此前建议的“显式启动参数或配置覆盖会话保存配置”没有获得确认；配置变更的操作入口仍待确定。
- Q18 已确认：会话数据存放于用户级统一根目录，例如 `~/.qhy-coding-agents/`，不采用工作区 `.agent/` 的建议。具体目录结构与工作区关联方式尚未确定。
- Q19 已确认：session transcript 包含用户与助手消息、工具往返、轮次完成或中断状态，以及运行配置和配置变更；恢复取最后生效配置，凭据从当前环境读取。
- Q20 已确认：保留压缩前原文，摘要仅用于模型输入。已通过 ADR 0007 明确替代 ADR 0004 中丢弃原文、仅成功轮次落盘的相关约定；ADR 0004 也增加部分取代说明。
- Q21 已确认：恢复构造模型上下文时，无结果调用过滤、有部分结果调用保留，原始 transcript 不删去调用记录；后续 Q24 将用户主动中断与断电的处理进一步区分，以 Q24 为准。
- Q22 已确认：不允许两个进程同时使用同一会话。
- Q23 已确认采用 A：保留逐行 CLI，使用斜杠命令和编号列表完成会话选择、检查点预览及恢复确认，不建设全屏 TUI。
- Q24 已确认区分中断原因：用户主动中断时，未完成工具调用的结果记录为精确字符串 `Interrupt by user`；断电后没有任何结果的调用在模型上下文中过滤，有部分结果的则保留。原始 transcript 仍完整保留记录。ADR 0003 关于取消时不补造结果的历史表述已增加对此用户中断标记的细化说明。
- Q25 已确认：会话选择默认展示当前工作区的会话，并提供查看全部会话的选项；底层数据仍统一存放于用户级根目录。
- Q26 已确认：不允许工作区搬家后重新绑定原会话。会话绑定原工作区路径，路径失效时恢复报错；不能将用户级统一存储解释为允许迁移工作区。
- Q27 已确认：将摘要与覆盖的历史范围写入 transcript，恢复时直接复用并接上后续消息，完整原文保留。
- Q28 已确认：transcript 写入失败时停止本轮，不启动后续模型请求或工具调用；已经发生的修改保留。此规则与检查点备份失败不影响编辑分开处理。
- Q29 已确认：本次不提供旧格式对话的导入或迁移。
- Q30 已确认：代码恢复的目标检查点、各文件实际成功或失败结果写入 transcript，并在后续模型上下文中提供给 Agent。
- Q31 已确认：会话记录、检查点和文件备份一直保留，不自动过期或清理。首版命令入口以 Q33 确认的集合为准。
- Q32 已确认：文件追踪与 `.gitignore` 无关；受支持工具可以合法修改或创建的目标，按统一规则追踪。
- Q33 已确认命令入口：`/new` 在当前工作区新建会话；`/resume [id]` 继续指定会话，省略 ID 展示选择列表；`/rewind` 选择消息级检查点、预览并确认代码恢复；`/exit` 退出。
- Q34 已确认：处理中 Ctrl+C 取消当前轮次、为未完成工具调用记录 `Interrupt by user`，随后返回输入提示符；空闲时 Ctrl+C 退出。与当前代码取消后直接退出的行为不同。
- Q35 已确认采用推荐边界：新会话使用启动配置，续聊使用 transcript 配置；首版不提供会话内配置编辑命令，transcript 保留记录配置变更的能力。
- Q36 已确认：首次文件备份作为此前检查点的恢复基线。用户确认的例子：消息 1 时文件为 A 但未追踪，手动改为 B，消息 2 首次工具修改前备份 B 后改为 C，则恢复消息 1 使用 B；未保存的 A 无法重建。
- Q37 已确认：恢复预览后、用户确认前文件再次变化时，刷新受影响文件和改动统计，再由用户确认。用户在澄清 `/rewind` 是文件恢复指令后接受此推荐。
- Q38 已确认：`/resume` 指定的会话不存在时报错，不隐式新建。
- 用户已确认整体设计并调用 to-spec，授权将现有讨论整理为正式规格；尚未授权实现。
- 用户已确认测试主入口：编译后 CLI 子进程、本地模型服务夹具、临时用户目录和工作区；观察输出、文件、落盘记录及后续模型请求。正式规格发布为 [spec.md](spec.md)，状态 `ready-for-agent`。

## 当前事实

- 访谈前的领域词汇表只定义了“对话”和“对话轮次”；当前实现尚无独立的会话实体。
- 当前历史文件保存消息数组；工作区及模型等运行配置在每次启动时重新读取，没有绑定到历史记录。
- 历史位于启动目录下的 `.agent/conversations/`，不跟随工作区；跨启动目录查找同一对话尚无统一入口。
- 仅成功轮次更新可续聊历史；失败、取消时保留上次成功历史，已经发生的工具副作用不回滚。
- 当前代码仍遵循 ADR 0004 原有的摘要替换与仅成功轮次保存方式；本次已确认的新设计通过 ADR 0007 替代相关约定，尚未实现。
- 内置文件修改工具目前只有 `write_file`，能够确定本地目标路径；Bash 无修改文件清单，MCP 无统一的本地文件映射或恢复协议。统一执行入口存在审批通过后、实际执行前的可等待位置；现有观察事件不等待回调完成，不能直接承担先保存再修改的保证。事实来源：`src/tool-registry.ts`、`src/workspace-files.ts`、`src/host-bash.ts`、`src/remote-mcp.ts`。

事实来源：`src/conversations.ts`、`src/cli.ts`、`GLOSSARY.md`、`docs/adr/0004-conversation-summary.md`。

## 设计树与当前状态

- 会话边界：同工作区多会话、共用目录、各自维护 transcript 和文件追踪；已确认。
- 会话恢复：transcript 为配置依据、用户级统一存储、禁止工作区重新绑定；已确认。
- 历史与摘要：完整原文保留，摘要及其覆盖范围可复用；已确认。
- 文件检查点：消息级、首次工具修改前追踪与备份、手动变化在新消息时捕获、首次备份作为早期基线；已确认。
- 代码恢复：预览与确认、变化后重新预览、保留对话、恢复结果进入上下文；已确认。
- 错误分支：备份失败继续、transcript 失败停止、缺失备份不恢复、执行中逐文件记错并继续；已确认。
- 中断与并发：用户中断标记、断电无结果过滤及部分结果保留、同会话禁止并发；已确认。
- 交互与范围：四个命令、处理中 Ctrl+C 返回输入、无 fork/旧历史导入/工作区迁移/会话内配置编辑；已确认。
- 实现约束与验收场景：见 [设计稿](design.md)。具体事件编码、目录层次和版本去重由实现阶段细化，不改变已确认业务语义。
- 最终共同理解：用户已确认设计稿，访谈结束；规格已整理发布，未开始实现。
