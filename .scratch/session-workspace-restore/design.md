# Session 工作现场恢复设计

状态：用户已确认。本文整理访谈已确认的业务规则与实现约束；正式需求见 [spec.md](spec.md)，尚未进入代码实现。

## 目标与会话边界

用户可以恢复之前会话的对话、运行配置和文件现场。一个工作区可有多个会话，共用同一工作目录；每个会话各自维护 transcript、检查点与文件追踪。继续或切换会话时，使用当前磁盘文件，不自动执行代码恢复。

数据统一存放于用户级根目录，默认采用 `~/.qhy-coding-agents/`。会话绑定原工作区路径；目录移动、改名或失效后，不提供重新绑定路径来继续原会话的功能。

## 交互入口

保留逐行 CLI，以斜杠命令和编号列表完成选择、预览和确认。

| 入口 | 行为 |
| --- | --- |
| `/new` | 在当前工作区新建空会话，建立初始配置记录 |
| `/resume [id]` | 继续指定会话；不传 ID 时展示会话选择列表 |
| `/rewind` | 选择消息级检查点，预览受影响文件与改动统计，确认后恢复代码 |
| `/exit` | 退出 CLI |

会话列表默认展示当前工作区的会话，并提供查看全部会话的选项。选择其他工作区的既有会话时，沿用该会话记录的原工作区，不把它重新绑定到当前目录。指定不存在的会话时报错，不按该 ID 自动新建。

新会话使用启动时提供的运行配置，工作区取当前工作区；续聊以 transcript 中最后生效的配置为准。凭据从当前环境解析，记录配置中的环境变量引用，不记录凭据值。首版不提供会话内配置编辑命令，transcript 保留记录配置变更的能力。

处理中按 Ctrl+C 取消当前轮次，记录用户中断后返回输入提示符；空闲时按 Ctrl+C 退出。同一会话不允许两个进程同时使用。

## Transcript 与模型上下文

Transcript 保存完整原文，包括用户与助手消息、工具往返、轮次完成或中断状态、运行配置及变更，以及摘要与代码恢复记录。失败、中断的轮次也保留。

模型输入可以用摘要替代较早消息；transcript 不删除对应原文。摘要内容及覆盖的历史范围一并保存，恢复时复用，再接上后续消息。摘要仍是历史资料，不改变内置系统提示或工具策略。

恢复时按以下规则构造工具上下文：

| 场景 | 模型上下文 |
| --- | --- |
| 工具已经返回完整结果 | 保留调用及对应结果 |
| 用户主动中断尚未完成的调用 | 结果记为精确字符串 `Interrupt by user` |
| 断电后，调用没有任何已保存结果 | 过滤本次工具调用，原始 transcript 中的记录保留 |
| 断电后，调用有已保存的部分结果 | 保留对应调用和真实部分结果 |

部分结果需明确表达尚未观察到最终结果，不填入未观察到的退出码或成功状态。模型输入仍须保持调用与结果的配对；不能直接发送孤立的工具调用。可保留的部分内容以实际收到且已保存的内容为准，未返回任何部分内容的工具按无结果处理。

## 文件追踪与检查点

首版由内置 `write_file` 触发追踪。Bash、MCP 不作为追踪入口，也不保证其任意副作用可恢复。已追踪文件的后续变化不按来源区分，在下一条消息的检查点中保存。

文件追踪与 `.gitignore` 无关，覆盖 `write_file` 可以合法修改或创建的目标。既有工作区与符号链接边界继续有效。

保存时机：

1. 新消息开始处理时，创建消息级检查点，检测已追踪文件的变化并保存当前版本。
2. 受支持工具准备修改或创建文件时，进入修改前备份流程；首次遇到的目标加入当前会话的追踪范围。创建前的“不存在”也是需要记录的文件状态。

同一消息多次修改同一文件时，该消息检查点的恢复目标保持修改前基线，不能被后续工具前版本覆盖。界面仅展示消息级检查点。

手动修改不会立即触发备份。例如：

| 时刻 | 保存与追踪行为 |
| --- | --- |
| 消息 1 开始 | 创建检查点 1 |
| 首次编辑 `a.ts` 前 | 备份 A，纳入追踪 |
| 助手修改 | 当前内容变成 B |
| 用户手动修改 | 当前内容变成 C，不立即备份 |
| 消息 2 开始 | 创建检查点 2，检测变化并备份 C |

检查点 1 恢复 A，检查点 2 恢复 C。

首次备份也是更早检查点的恢复基线。若消息 1 时文件为 A、尚未追踪，用户手动改成 B，消息 2 首次工具修改前才备份 B，则恢复消息 1 使用 B；未保存的 A 无法重建。

## 代码恢复

用户通过 `/rewind` 选择检查点。先检查必要备份是否齐全，再显示受影响文件和改动统计，由用户选择是否恢复。

预览不识别修改来自用户、其他会话或其他进程，不增加针对“手动修改被覆盖”的单独提示。若预览后、确认前文件再次变化，刷新文件列表与统计，再由用户确认。

恢复只作用于当前会话追踪范围内的文件。未追踪文件保持现状；已追踪且目标检查点状态为“不存在”的文件，在恢复时删除并在预览中列明。

恢复代码保留全部对话。目标检查点、各文件成功或失败的结果写入 transcript，在后续模型上下文中呈现。之后的新消息按恢复后的实际文件状态建立检查点。

## 错误行为

| 错误 | 处理 |
| --- | --- |
| 检查点或文件备份失败 | 记录错误并返回，继续消息处理与编辑 |
| Transcript 写入失败 | 停止本轮，不启动后续模型请求或工具调用；保留已发生的文件修改 |
| 恢复前缺少必要备份 | 不开始恢复，不能只恢复有备份的文件 |
| 恢复过程中单文件写入失败 | 记录该文件错误，继续处理其余文件 |
| 指定会话不存在 | 报错 |
| 原工作区路径失效 | 恢复报错，不重新绑定路径 |
| 同一会话已被另一进程使用 | 拒绝同时使用 |

例如恢复 `a.ts` 成功、恢复 `b.ts` 失败后，仍继续恢复 `c.ts`。备份完整性检查不代表执行阶段具有多文件事务原子性。

## 实现约束

- 记录需随处理过程持续保存，不能继续仅在成功轮次结束后整份保存；断电恢复以已经成功保存的记录为依据。
- 摘要和完整记录分开表达；原文留存不意味着每次请求都发送全部原文。
- 工具执行前备份必须接入可等待的执行路径，不能只挂在不等待完成的观察事件上；审批和路径校验继续有效。
- 同一会话的进程占用需在正常退出后解除，异常退出后也应允许再次恢复，不能永久卡在占用状态。
- 半写入的记录不能污染此前完整记录；不可恢复的记录损坏应明确报错。
- 会话记录、检查点及文件备份一直保留，不自动过期或清理。
- 具体事件编码、用户根目录内部层次、版本去重及占用检测方式由实现阶段细化，不改变上述业务语义。

## 验收场景

以下是后续实现的公共行为验收要求，本次尚未运行实现测试。

| 场景 | 预期 |
| --- | --- |
| 从不同启动目录继续同一会话 | 使用用户级数据及原工作区，配置取自 transcript |
| 同工作区切换多个会话 | 各自恢复历史、配置和追踪范围，磁盘文件不自动还原 |
| 摘要后跨进程恢复 | 原文仍在，复用摘要及覆盖范围 |
| 工具编辑后手动改文件，再发送消息 | 新检查点保存手动修改后的版本 |
| 首次追踪发生在较晚消息 | 较早检查点使用首次备份基线 |
| 恢复到追踪文件创建前 | 删除该文件，保留未追踪文件 |
| 恢复期间保留对话 | 原消息继续存在，追加恢复结果供 Agent 使用 |
| 备份失败与 transcript 失败 | 前者继续编辑，后者停止本轮 |
| 必要备份缺失 | 恢复前失败，不先修改一部分文件 |
| 恢复中某个文件失败 | 记录错误，继续剩余文件 |
| 预览后文件又变化 | 更新预览，重新确认 |
| 用户中断 | 未完成调用结果为 `Interrupt by user`，CLI 返回输入 |
| 断电后恢复工具调用 | 无结果调用过滤，有部分结果调用保留，原记录不删 |
| 两个进程使用同一会话 | 第二个进程被拒绝，原进程不受影响 |
| 原工作区移动、改名或不存在 | 恢复失败，不迁移绑定 |
