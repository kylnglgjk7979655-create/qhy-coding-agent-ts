# 交互式 CLI 文件工具 QA 清单

依据：[spec.md](./spec.md)、[交互式对话票据](./issues/01-interactive-conversation.md)、[读取文件票据](./issues/02-read-file.md)、[写入文件票据](./issues/03-write-file.md)。下文 S1–S26 对应 spec 中编号相同的 User Story。

本文件是待执行清单，不代表全部用例已通过。执行后再勾选，并在末尾记录提交、结果和证据。

## 执行准备

- [ ] 使用项目锁定的 Node.js 24.22.2、pnpm 9.12.3；运行 `pnpm check`，记录类型检查、构建及测试结果。
- [ ] 自动化验证使用编译后的 CLI、本地 OpenAI 兼容 HTTP fixture 和临时工作区；只向本地 fixture 提供假凭据。fixture 能指定文本、工具调用、错误、延迟和截断响应，并检查下一次请求中的历史及工具结果。
- [ ] 人工验证使用真实终端中的 `pnpm dev`，另用编译后的 CLI 复核；真实模型验收前按现有方式配置凭据。

在仓库根目录准备独立测试文件；保留同一个终端中的 `qa_root` 变量供后续命令使用：

```sh
qa_root="$(mktemp -d)"
mkdir -p "$qa_root/workspace/subdir" "$qa_root/workspace-sibling"
printf '第一行：QA_READ_MARKER\n第二行：原始内容\n' > "$qa_root/workspace/note.txt"
printf 'QA_OUTSIDE_MARKER\n' > "$qa_root/outside.txt"
printf 'QA_SIBLING_MARKER\n' > "$qa_root/workspace-sibling/note.txt"
ln -s "$qa_root/outside.txt" "$qa_root/workspace/escape.txt"
ln -s "$qa_root" "$qa_root/workspace/escape-dir"
ln -s "$qa_root/workspace/note.txt" "$qa_root/workspace/inside.txt"
ln -s "$qa_root/not-created.txt" "$qa_root/workspace/dangling.txt"
pnpm dev --workspace "$qa_root/workspace" 2> "$qa_root/dev-run.jsonl"
```

会话历史仍位于启动目录的 `.agent/conversations/`，不会因为 `--workspace` 改到临时工作区。每组会修改文件的用例执行前，恢复对应测试文件的初始内容。

## 1. 交互与会话续接（S1–S11）

- [ ] **QA-01 启动即等待输入**：不传位置参数启动 CLI；出现输入提示，在用户输入前不发送模型请求。
- [ ] **QA-02 单轮回答**：输入一条消息；出现非空回答，当前轮次完成后再显示下一次输入提示。
- [ ] **QA-03 多轮上下文**：先输入“记住代号 QA_CONTEXT_42”，再询问代号；fixture 的第二轮请求包含上一轮用户消息和 Agent 回复，真实模型能据此回答。
- [ ] **QA-04 轮次串行**：第一轮响应挂起时继续提交第二条输入；第一轮完成前不发起第二轮模型请求，回答不会交错。
- [ ] **QA-05 正常退出**：启动后直接输入 `/exit`，以及成功回答后输入 `/exit`；均正常退出，不将退出命令发送给模型或保存为用户消息。
- [ ] **QA-06 新建会话 ID**：不提供 ID，完成首轮；`run.started`、`run.finished` 中可获取相同的 `conversationId`，并能用它定位保存的历史。
- [ ] **QA-07 成功轮次完整保存**：完成“读取→写入→最终回答”；历史按顺序保存用户消息、工具调用、工具结果和 Agent 回复，文件内容有效且可再次加载。
- [ ] **QA-08 跨进程恢复**：退出后重新启动 `pnpm dev --workspace "$qa_root/workspace" --conversation-id <实际ID>`；下一次模型请求包含此前完整上下文，成功轮次追加到同一个会话。
- [ ] **QA-09 失败轮次不保存**：先成功一轮，再由 fixture 返回 provider 错误或截断回答；失败后历史与失败前一致，不混入失败轮次的消息、部分回答或工具往返。
- [ ] **QA-10 失败后恢复**：QA-09 后继续输入；显示失败原因并接受下一条消息，新请求仅包含此前成功历史和当前消息，后续成功轮次正常保存。

## 2. 文件读取、写入与工具往返（S12–S16、S20–S22）

- [ ] **QA-11 读取内容回传**：让 Agent 读取 `note.txt`；下一次 provider 请求包含实际文件内容，Agent 在收到结果后给出最终回答。
- [ ] **QA-12 根据读取结果修改**：先读取 `note.txt` 再修改；最终文件为预期完整内容，模型收到写入成功结果，终端出现最终回答。
- [ ] **QA-13 完整替换**：将原来的多行文件写为单行较短文本；核对文件字节内容，没有追加文本或残留旧内容。
- [ ] **QA-14 创建新文件**：写入 `subdir/new.txt`；父目录已存在时成功创建文件，无逐次确认提示。
- [ ] **QA-15 空内容与中文**：分别写入空字符串、中文和换行；空字符串使文件变为空文件，其余内容按 UTF-8 原样保存。
- [ ] **QA-16 缺失父目录**：写入 `missing/new.txt`；返回工具错误，不创建 `missing` 目录，模型收到错误后可以回答或选择下一步。
- [ ] **QA-17 读取失败**：读取不存在的文件或无权访问的文件；错误作为工具结果回传，不导致 CLI 直接崩溃，模型能继续完成回答。
- [ ] **QA-18 写入失败**：向目录路径或不可写文件写入；返回可处理的工具错误，原内容不被错误地报告为修改成功。权限用例使用普通用户运行。
- [ ] **QA-19 工具错误后继续处理**：fixture 先请求一个失败的文件操作，再请求有效操作；错误结果出现在下一次请求中，随后有效操作和最终回答均完成。
- [ ] **QA-20 工具输出简洁**：fixture 调用文件工具并最终只回复“操作完成”；终端显示 `[工具] read_file`、`[工具] write_file`，不直接打印工具参数、文件内容或完整结果对象。

QA-20 检查的是程序直接打印的工具信息。用户要求查看内容时，Agent 的最终回答可以引用文件内容。

## 3. 工作区路径边界（S17–S19，读写均需验证）

每项分别调用 `read_file` 和 `write_file`。拒绝读取时，确认工作区外标记未进入任何 provider 请求；拒绝写入时，确认外部文件未改变、外部新文件未创建。

- [ ] **QA-21 相对路径**：从仓库根目录启动、workspace 指向临时目录；`note.txt` 命中临时工作区内文件，而非启动目录中的同名文件。
- [ ] **QA-22 区内绝对路径**：使用 `$qa_root/workspace/note.txt` 的实际绝对路径；读写均成功。
- [ ] **QA-23 路径穿越**：请求 `../outside.txt`，并尝试 `../new-outside.txt`；返回工具错误，不泄露或修改外部文件，不在外部创建文件。
- [ ] **QA-24 区外绝对路径**：请求 `$qa_root/outside.txt`；读写均拒绝。
- [ ] **QA-25 相似目录前缀**：请求 `$qa_root/workspace-sibling/note.txt`；不能因为路径前缀相似而放行。
- [ ] **QA-26 文件符号链接越界**：请求 `escape.txt`；读写均拒绝，外部 `outside.txt` 保持原样。
- [ ] **QA-27 父目录符号链接越界**：请求 `escape-dir/outside.txt`，并尝试写入 `escape-dir/new-outside.txt`；已有文件和新文件目标均被拒绝。
- [ ] **QA-28 区内符号链接**：请求 `inside.txt`；读到 `note.txt` 的内容，写入后更新区内目标文件。
- [ ] **QA-29 悬空符号链接**：请求 `dangling.txt`；返回工具错误，不在区外创建其链接目标。

## 4. 配置、步数、超时与取消（S23–S25、Implementation Decisions）

- [ ] **QA-30 配置保留**：验证默认配置、`--config`、`--workspace` 覆盖、`.env` 凭据、环境变量优先级；provider 请求使用指定模型和服务地址，日志不输出密钥。
- [ ] **QA-31 配置失败**：缺少凭据、配置无效或工作区不存在时，在模型请求前报 `CONFIG_ERROR`，退出码为 2。
- [ ] **QA-32 步数上限**：配置 `maxSteps: 1`，让 fixture 持续返回工具调用；记录 `STEP_LIMIT`，该轮次不保存，CLI 仍接受下一条消息。
- [ ] **QA-33 每轮独立计步**：在同一进程内完成或失败一轮后，再输入新消息；新轮次重新计算步数，不消耗上一轮剩余额度。
- [ ] **QA-34 总超时**：让模型请求或多步工具循环超过 `timeoutMs`；记录 `TIMEOUT`，未完成轮次不保存，随后仍能处理正常消息。
- [ ] **QA-35 等待输入时 Ctrl+C**：在真实终端分别通过 `pnpm dev` 和编译后的 CLI 启动，不发送消息就按 Ctrl+C；及时退出，不新增会话轮次，退出码为 130。
- [ ] **QA-36 请求期间 Ctrl+C**：fixture 挂起当前模型请求后，在真实终端按 Ctrl+C；请求连接及时关闭，记录 `CANCELLED`，无需等待模型返回或超时，退出码为 130。
- [ ] **QA-37 已输出部分内容时 Ctrl+C**：fixture 先流式返回一段内容，再挂起；按 Ctrl+C 后停止继续生成，不将部分回答保存为成功轮次，已有成功历史保持不变。
- [ ] **QA-38 取消后的文件操作**：在模型下一步工具调用尚未返回时取消；其后不再开始新的文件操作，也不保存取消轮次。取消前已完成的写入不要求回滚。
- [ ] **QA-39 进程信号取消**：另行向请求中的进程发送 SIGINT；同样以取消状态退出。此项不能替代 QA-35–QA-38 的真实终端按键验证。
- [ ] **QA-40 runtimeInfo 保留**：在普通对话中调用 `runtimeInfo`；工具可用，结果回传模型并完成回答。
- [ ] **QA-41 日志终态**：成功、失败、取消分别核对 `runId`；每个已开始的轮次对应一个终态，取消不能重复记录相同轮次的失败终态。

## 5. 工具冒烟（S26、Testing Decisions）

```sh
pnpm build
pnpm exec node dist/cli.js --workspace "$qa_root/workspace" --smoke-tool
```

- [ ] **QA-42 冒烟成功**：首步强制 `read_file`；确实执行读取，结果进入下一次 provider 请求，最终回答使用实际探针内容，记录 `toolSmokePassed: true`，退出码为 0。
- [ ] **QA-43 探针独立性**：检查第一轮 provider 请求；探针内容不能从提示词、文件名或其他工具的输出中提前获得，探针文件名与内容分别生成。
- [ ] **QA-44 忽略结果不能通过**：fixture 执行读取后，最终只回显原始提示词，或返回不含探针的固定回答；均应判为 `TOOL_COMPATIBILITY_ERROR`，退出码为 6。重点防止“文件名包含探针”造成误通过。
- [ ] **QA-45 工具未执行不能通过**：fixture 忽略强制工具选择或不完成有效读取；冒烟失败，不记录通过。
- [ ] **QA-46 真实服务验收**：使用现有真实 provider 配置运行上述命令；确认成功标准与 fixture 相同，而非仅检查回答非空。此项会产生真实 API 用量。
